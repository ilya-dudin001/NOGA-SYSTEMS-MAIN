# EM 3.5 — Operations. Дизайн-система

Тёмная luxury-система, снятая с макетов в `reference/`. Без сборки и фреймворков:
CSS-переменные, готовые классы, ванильный JS — как и остальной фронтенд проекта.

Живой гайд: открыть `design-system/index.html` в браузере (или
`python -m http.server` из корня и зайти на `/design-system/`).

## Файлы

| Файл | Что внутри |
|------|-----------|
| `tokens.css` | все токены: цвет, типографика, сетка, радиусы, тени, движение |
| `tokens.json` | те же токены машинно-читаемо, с замеренными значениями и причинами правок |
| `base.css` | сброс, базовая типографика, `:focus-visible`, `prefers-reduced-motion` |
| `components.css` | компоненты и все их состояния |
| `icons.js` | SVG-спрайт: 40 иконок + логотип, `window.EmIcons` |
| `ds.js` | поведение: табы, сегменты, статусы, загрузка фото, таймлайн, валидация, `window.EmDS` |
| `showcase.css` | оформление самой страницы-гайда, в приложении не нужен |
| `index.html` | живой гайд: токены, компоненты, состояния, пять экранов, список правок |
| `tools/audit.js` | статическая проверка системы, `node design-system/tools/audit.js` |

## Подключение

```html
<link rel="stylesheet" href="design-system/tokens.css">
<link rel="stylesheet" href="design-system/base.css">
<link rel="stylesheet" href="design-system/components.css">
<script src="design-system/icons.js"></script>
<script src="design-system/ds.js"></script>
```

`ds.js` сам вызывает `EmDS.init(document)` на `DOMContentLoaded`. После того как
вставили разметку динамически, нужно позвать `EmDS.init(root)` и
`EmIcons.hydrate(root)` для нового поддерева.

Иконка в разметке — пустой элемент с `data-em-icon`; он заменяется на `<svg>`,
классы переносятся:

```html
<span class="em-btn__icon" data-em-icon="home"></span>
<span class="em-navtab__icon" data-em-icon="doc" data-em-title="Операции"></span>
```

Без `data-em-title` иконка декоративная (`aria-hidden`), с ним — картинка с подписью.

## Как значения снимались

Макеты — растровые рендеры, поэтому «на глаз» не годилось:

1. PNG декодировался напрямую (zlib + расфильтровка сканлайнов), без зависимостей.
2. Цвет поверхности — среднее по области без текста; цвет акцента — самый насыщенный
   пиксель области (общий тёплый grade рендера иначе занижает насыщенность).
3. Геометрия — пороговые пробеги по строкам и колонкам: границы карточек, ширина
   и зазоры плиток, радиусы по ASCII-карте угла.
4. Кегли — по высоте глифов (капитель ≈ 0.715em), затем нормировка к ширине 390px.
5. Контраст — WCAG 2.1 для каждой пары «текст на поверхности».
6. Логотип — карта яркости области 120×150px в сетке 60×50: по ней видно, что монограм
   собран из трёх вложенных линий на половину (внешняя нога с диагональю плеча, средняя
   линия, центральная стойка с шевроном) и хвостов с вырезом внизу. Отсюда `viewBox 48×60`.

Ключевые замеры и куда они попали — в `tokens.json` (поля `measured`, `fixed`, `reason`).

## Проверка

```bash
node design-system/tools/audit.js
```

Скрипт падает, если в разметке есть класс без стилей, иконка вне набора, токен без
объявления, hex-цвет вне `tokens.css`, `font-size` в пикселях, `transition: all`,
несбалансированный тег или слово «курьер». Неиспользованные токены он только
перечисляет: шкалы (отступы, оттенки золота, z-слои) держим полными.

## Состояния

Каждый интерактивный компонент закрывает набор: `default`, `hover`, `:active`
(pressed, `scale(.975)`), `:focus-visible` (золотой двойной контур),
`disabled`, `is-loading`, `is-success`, `is-error`, выбранное состояние
(`aria-selected` / `aria-current` / `.is-selected`). Состояния — на классах
`is-*` и ARIA-атрибутах, а не на отдельных цветовых классах.

## Движение

Длительности 120–320ms, только ease-out, смещения до 8px. Каскад в списках —
шаг 45ms через переменную `--i`. Всё выключается при `prefers-reduced-motion`.

## Отношение к текущему коду приложения

Классы намеренно с префиксом `em-`: в `assets/css/*` уже есть `.btn-gold`, `.stat`,
`.status-pill`, `.tabbar` и другие имена, и одновременное подключение не должно
ничего сломать. Перевод экранов — по одному, соответствия:

| Сейчас | В системе |
|--------|-----------|
| `.btn-gold` | `.em-btn.em-btn--primary` |
| `.btn-ghost` | `.em-btn.em-btn--ghost` |
| `.btn-icon` | `.em-btn-icon` |
| `.stat`, `.stats` | `.em-stat`, `.em-stats` |
| `.status-pill`, `.trubka-status` | `.em-pill`, `.em-status` |
| `.tabbar`, `.tab`, `.fab` | `.em-tabbar`, `.em-navtab`, `.em-fab` |
| `.tabs`, `.tabs__btn` | `.em-tabs`, `.em-tab` |
| `.segmented`, `.segmented__btn` | `.em-seg`, `.em-seg__btn` |
| `.field`, `.form-card` | `.em-field`, `.em-control`, `.em-card` |
| `.file-upload`, `.file-item` | `.em-upload`, `.em-upload__preview` |
| `.users-toolbar` | `.em-header` |

Терминология проекта обязательна и здесь: исполнитель — **нога**, слово «курьер»
не встречается ни в разметке, ни в подписях, ни в комментариях.

## Правки макета

Полный список с причинами — в разделе 14 гайда (`index.html#fixes`). Коротко:
контраст статусов и приглушённого текста, обрезанный текст в пилюле, высота полей
и зон нажатия, затемнение под фотографией в блоке оборота, статус не только цветом,
состояния фокуса, развёрнутые подписи фильтров, подписи у иконок в денежных строках,
табличные цифры в списках, FAB перестал перекрывать подписи, маркер обязательных
полей и состояние ошибки, город и нога в плашке дашборда без многоточия,
«Выберите ногу» вместо «Выберите сотрудника», уважение к `prefers-reduced-motion`
и `prefers-contrast`.
