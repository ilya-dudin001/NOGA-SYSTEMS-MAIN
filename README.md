# NOGA Systems

Telegram-бот + Mini App для учёта операций. Доступ по allowlist (`telegram_id`) с ролями Owner / Правая рука / Администратор / Нога.

- Фронтенд (GitHub Pages): https://ilya-dudin001.github.io/NOGA-SYSTEMS-MAIN/
- Backend: `backend/` (FastAPI + aiogram + SQLite)

Подробный контекст для разработки: [AGENTS.md](AGENTS.md).
Обновление боевого сервера: [DEPLOY.md](DEPLOY.md).

## Быстрый старт (локально)

### 1. Backend

```bash
cd backend
python -m venv .venv

# Windows
.venv\Scripts\activate
# Linux/macOS
# source .venv/bin/activate

pip install -r requirements.txt
copy .env.example .env   # или: cp .env.example .env
```

Заполните `.env`:

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен от @BotFather |
| `JWT_SECRET` | Длинная случайная строка |
| `OWNER_TELEGRAM_IDS` | Ваш Telegram ID (узнать у @userinfobot) |
| `WEBAPP_URL` | URL Mini App |
| `CORS_ORIGINS` | Origin фронта через запятую |
| `DEV_AUTH_ENABLED` | `true` для входа из браузера без Telegram |
| `DEV_AUTH_SECRET` | Секрет для `POST /api/auth/dev` |

Запуск:

```bash
mkdir data
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Проверка: `GET http://127.0.0.1:8000/api/health` → `{"status":"ok"}`.

Бот стартует вместе с API (long polling). Напишите боту `/start` с аккаунта из `OWNER_TELEGRAM_IDS`.

### 2. Frontend

Откройте `index.html` через любой static server (или GitHub Pages).

По умолчанию API: `http://127.0.0.1:8000`. Переопределение:

```
index.html?api=https://your-vps.example.com
```

или до загрузки скриптов:

```html
<script>window.__NOGA_CONFIG__ = { apiBase: "https://your-vps.example.com" };</script>
```

В браузере без Telegram появится форма Dev-входа (нужны `DEV_AUTH_ENABLED=true` и пользователь в БД).

### 3. BotFather

1. Создайте бота, скопируйте токен в `.env`.
2. `/setmenubutton` или кнопка из `/start` → URL = `WEBAPP_URL`.
3. Для продакшена Mini App должен быть на **HTTPS**.

## Деплой на VPS

Фронтенд уезжает на GitHub Pages сам после пуша в `main`. Backend обновляется на сервере:

```bash
ssh user@ваш-сервер
sudo bash /opt/noga/backend/deploy/deploy.sh
```

Скрипт делает `git pull`, при необходимости переустанавливает зависимости, снимает бэкап
базы, накатывает миграции и перезапускает `noga-api` с проверкой `/api/health`.

Первичная установка, ручной деплой по шагам, откат, Docker-вариант и диагностика —
в [DEPLOY.md](DEPLOY.md). Готовый systemd-unit: `backend/deploy/noga-api.service`.

Перед CORS укажите `https://ilya-dudin001.github.io` в `CORS_ORIGINS`.  
На фронте выставьте `apiBase` на публичный URL API (HTTPS).

## Команды бота

| Команда | Кто | Описание |
|---------|-----|----------|
| `/start` | allowlist | Кнопка WebApp |
| `/whoami` | allowlist | Профиль |
| `/users` | manage/read | Список |
| `/adduser <id> <role>` | manage | Добавить |
| `/setrole <id> <role>` | manage | Сменить роль |
| `/block` / `/unblock` | manage | Блок |
| `/deleteuser <id>` | owner | Удалить (с подтверждением) |

Роли: `owner`, `right_hand`, `admin`, `noga`.

Удаление доступно только Owner — и в боте, и в Mini App (кнопка «Удалить» на карточке
пользователя). Себя удалить нельзя. После удаления выданный ранее JWT перестаёт
работать сразу же: `/api/me` вернёт 401.

## API (кратко)

- `POST /api/auth/telegram` — `{ "initData": "..." }` → JWT + профиль
- `POST /api/auth/dev` — только при `DEV_AUTH_ENABLED`
- `GET /api/me` — профиль и `permissions`
- `PATCH /api/me` — `{ "display_name": "..." }`, свой ник (кроме роли «Нога»)
- `GET|POST /api/users`, `PATCH|DELETE /api/users/{id}`
- `GET|POST /api/cities`, `GET|PATCH|DELETE /api/cities/{id}`
- `GET|POST /api/nogas`, `GET|PATCH|DELETE /api/nogas/{id}`
- `POST /api/nogas/{id}/files` (multipart: `kind`, `file`), `GET|DELETE /api/nogas/{id}/files/{file_id}`
- `GET|POST /api/razgruzy`, `PATCH|DELETE /api/razgruzy/{id}`
- `GET|POST /api/trubki`, `GET|PATCH|DELETE /api/trubki/{id}` — заказы; читают все,
  создают и правят все роли кроме «Ноги»
- `GET /api/dashboard/summary` — оборот нулевой, блоки `cities` и `trubki` живые

Миграции Alembic: `alembic upgrade head` (из `backend/`). При старте также вызывается `create_all` + bootstrap Owner.

Миграция `003_city_status_razgruzy` заменяет у города флаг `is_active` на статус:
выключенные города переезжают в «На стопе (полностью)», остальные — в «В работе».
`004_noga_personal` добавляет ноге адрес, телефоны и Telegram, делает город
необязательным и создаёт таблицу `noga_files`. `005_noga_city_history` добавляет
`initial_city_name` и `last_city_name` (у уже прикреплённых ног обе заполняются
текущим городом). `006_trubki` создаёт таблицу заказов `trubki`.

Если рабочая база была создана через `create_all` и таблицы `alembic_version` в ней нет,
перед обновлением отметьте текущую ревизию, иначе Alembic начнёт с самого начала и
упрётся в уже существующие таблицы:

```bash
alembic stamp 003_city_status_razgruzy   # ревизию под своё состояние см. в DEPLOY.md
alembic upgrade head
```

## Управление ногами

Нога — исполнитель, привязанный к городу. У ноги есть имя, город и признак
**Тест / Не тест** (тестовые ноги помечаются бейджем и в будущем не пойдут в
реальный оборот). Отдельно от этого есть роль `noga` — это доступ к боту, а
ноги из справочника аккаунтов не требуют.

Экран открывается вкладкой «Ноги» в нижней панели. Owner и Правая рука видят все ноги.
Администратор ведёт свой участок: в списке только заведённые им ноги, и править,
выключать и удалять он может тоже только их. Так же устроены города и разгрузы.

Города — отдельный справочник. В форме ноги (и при создании, и при
редактировании) можно выбрать существующий город, «Без города» или
«+ Новый город» — он создастся вместе с ногой. Совпадение имени ищется без учёта
регистра, поэтому «тула» не создаст дубликат для «Тула». Пара имя + город
уникальна: одинаковых ног в одном городе не будет.

Указанный город прикрепляет ногу сразу: она появляется в списке ног в деталях
города, даже если раньше в городе ног не было. Открепить или перекинуть ногу
можно и с экрана ноги (город «Без города»), и из формы города — там есть
чек-лист ног.

На карточке ноги три кнопки-иконки, как у города: развернуть, изменить и удалить.
Переключатели «Сделать тестовой» и «Выключить» лежат внутри, во вкладке «Основное»,
чтобы список читался с одного взгляда: имя, город, бейдж типа.

История городов сохраняется: в деталях серым видно, к какому городу ногу прикрепили
при заведении и к какому она была прикреплена последней (если это один и тот же город —
одна строка). История остаётся даже после удаления города, так что видно, откуда нога
пришла, даже если сейчас она без города.

### Личные данные ноги

В деталях ноги («Подробнее») две вкладки: «Основное» и «Личные данные». На второй:

- **Фото паспорта**, **паспорт вместе с лицом**, **короткое видео с лицом** — по
  каждому блоку можно загрузить сколько нужно файлов, посмотреть их прямо в
  приложении, скачать и удалить. Загрузка необязательна. Принимаются популярные
  форматы картинок, включая apple-овские HEIC/HEIF (до 25 МБ), и видео mp4, mov,
  webm, m4v, 3gp, mkv (до 200 МБ). HEIC браузер иногда не рисует — тогда вместо
  предпросмотра появится подсказка и файл можно скачать.
- **Домашний адрес**.
- **Номера телефонов** — поле можно клонировать кнопкой «+ Добавить», лишние
  строки убираются крестиком.
- **Контакты Telegram** — так же клонируются.

Личные данные доступны Owner, Правой руке и Администраторам (право `nogas:personal`),
причём Администратору — по любой ноге, в том числе чужой: если нога другого админа
пропала со связи, с ней нужно уметь связаться напрямую. Карточка чужой ноги при этом
только для чтения — открыть её можно из деталей города, кнопкой рядом с именем ноги.
Файлы лежат на сервере в `UPLOADS_DIR` (по умолчанию `backend/data/uploads`), в базе
только метаданные; удаление ноги удаляет и её файлы.

## Управление городами

Экран «Города» открывается плашкой на дашборде (тап по сводке) или вкладкой «Города»
в нижней панели. Плашка показывает сводку по всей системе:
сколько городов в работе, на временном и на полном стопе, а также общее число ног
и разгрузов — ноги разных админов в одном городе просто складываются, чьи они, видно
только в деталях города.

Наверху экрана переключатель списков:

- **Мои города** (у Owner и Правой руки — «Все города») — свой участок. Для админа это
  города, которые он завёл, плюс чужие, где стоят его ноги: такие видно, но не изменить.
- **В работе** — общая витрина: города в работе от всей команды. Её открывает плашка
  на дашборде.

У города есть:

- **Статус**: «В работе», «На стопе (временно)», «На стопе (полностью)». Переключается
  прямо на карточке, без захода в форму. Город в работе без единой ноги помечается
  красным предупреждением «!! ВНИМАНИЕ !! К городу не прикреплена нога» и красным
  статусом — и в списке, и в деталях. Такой же меткой «!! ГОРОД БЕЗ РАЗГРУЗА !!»
  отмечается город в работе, к которому не привязан ни один разгруз — например, после
  удаления последнего. Поставить «В работе» городу без ног можно только после
  подтверждения.
- **Порог запуска** — произвольная сумма и валюта: рубли, доллары, узбекские сумы,
  киргизские сомы, казахские тенге, азербайджанские манаты, белорусские рубли,
  молдавские леи, приднестровские рубли. Сумма и валюта задаются только вместе.
- **Ноги** — подтягиваются из справочника ног по привязке к городу: имя, тест/рабочая,
  кто добавил и когда; в одном городе спокойно уживаются ноги разных админов. Каждую
  ногу можно раскрыть прямо здесь и посмотреть её карточку с личными данными. В форме
  города есть чек-лист ног: отмеченные работают в этом городе, снятые открепляются, —
  но в нём только свои ноги, чужие город не покидают. В подписи видно, где нога сейчас —
  «без города» или «сейчас в Самаре».
- **Разгрузы** — несколько на город, один разгруз может обслуживать несколько городов.
  По каждому видно комиссию, контакт, кто добавил, дату и сколько заказов через него
  успешно разгружено. Когда вы создаёте новый город, ваши разгрузы отмечаются в форме
  сразу — лишние можно снять, чужие добавить вручную.
- **Последние 5 заказов** — раздел готов, но пока пуст: трубки в карточку города ещё
  не подставляются, они живут на своих экранах.

Город можно добавить, изменить, удалить и переключить его статус — действия на карточке
собраны в кнопки-иконки: шеврон (подробнее), карандаш (изменить), корзина (удалить).

Если к городу прикреплены ноги, перед удалением приложение перечислит их по именам и
предупредит, что ноги автоматически с города снимутся. На «Да» ноги открепляются
(сами остаются в системе), и только потом удаляется город. Owner и Правая рука правят
любые города; Администратор — только заведённые им: у чужого города остаётся одна
кнопка «Подробнее» и подпись, кто его ведёт.

## Разгрузы

Отдельный экран «Разгрузы»: название, комиссия в процентах, контакт, включён/выключен.
Справочник общий — разгрузы всей команды видит каждый, кому они вообще показываются, и
любой из них можно привязать к своему городу. А вот изменить, выключить или удалить
разгруз может только тот, кто его завёл; Owner и Правая рука — любой. Роль «Нога»
разгрузы не видит вообще — ни на своём экране, ни в составе города.

Если разгруз привязан к городам, при удалении приложение перечислит их по именам и
предупредит, что города автоматически от него отвяжутся. На «Да» связи снимаются, и
только потом удаляется сам разгруз — города остаются на месте. Те из них, что работают
и остались вовсе без разгрузов, сразу получают на карточке метку
«!! ГОРОД БЕЗ РАЗГРУЗА !!».

## Трубки (заказы)

Трубка — это заказ: город, нога, сумма и стадия работы. Ручные статусы:
**Зацеп**, **Забрали**, **Выплачено**, **Срез**. Новая трубка получает «Зацеп».
После пересчёта и фото денег автоматически ставится **Разгружается**, а после ввода
суммы захода USDT — **Выплачено**.

На дашборде вместо прежней «Статистики на сегодня» стоит блок **«Трубки»** — таблица
последних заказов со столбцами «Статус / Город / Сумма / Нога / Чья нога» и счётчиком
всего. Если названия длинные, таблица прокручивается вбок пальцем. Кнопка «Все трубки»
открывает полный список с фильтром по стадии.

Создание двухшаговое: сначала статус и город, затем сумма и нога выбранного города.
После создания сразу открывается страница трубки. В ней вводится пересчёт, а выплата
ноге 10% и остаток считаются моментально. Кнопка «Пересчёт» доступна после загрузки
фото денег. Затем появляются сумма «Зашло на счёт, USDT», фото чека и кнопка
«Отправить отчёт».

ФИО, адрес и способ передачи необязательны и скрыты под дропдауном «Данные клиента».
История хранит создание, суммы, загрузки фото, смены статуса и отправку отчёта с актором
и полной датой; в карточке показываются время и краткое описание.

Заказы видит вся команда, включая роль «Нога», — список общий, деления по участкам у
трубок нет. Заводить, править и удалять их могут все роли кроме «Ноги». Пока на городе,
ноге или разгрузе висит хотя бы одна трубка, удалить их нельзя: приложение скажет,
сколько заказов мешает.

## Кнопка «+»

Круглая кнопка в центре нижней панели раскрывает вылетающее меню: **Трубка**, **Город**,
**Нога**, **Разгруз**. Каждый пункт сразу открывает нужный экран с готовой формой.
Список собирается по правам — пункты, которых вам нельзя, не появляются вовсе.
Закрыть меню можно тапом по затемнению или клавишей Esc.

## Профиль

Вкладка «Профиль» в нижней панели — личный кабинет и вход в свои разделы. Сверху карточка:
инициалы, имя и роль. Telegram ID, username, статус, дата регистрации и последний вход
спрятаны под строкой «Детали профиля» — она разворачивается по нажатию.

Кнопка-карандаш рядом с ником есть у Owner, Правой руки и Администратора: ник можно
писать русскими и английскими буквами с цифрами, между словами допустимы пробел, дефис и
подчёркивание, длина от 2 до 32 символов. Новое имя сразу подставляется в шапку панели.
У роли «Нога» такой кнопки нет — её имя ведёт тот, кто её завёл.

Бирка роли стоит справа от аватара. Ниже — список разделов, каждый открывается отдельной страницей:

- **Пользователи** — у Owner и Правой руки, то есть у тех, кто пользователями управляет.
  Администратор список читать может, но только с дашборда: править его он всё равно не вправе.
- **Мои города** / **Мои ноги** / **Мои разгрузы** — свой участок. У Owner и Правой руки
  скоуп общий, поэтому пункты называются просто «Города», «Ноги» и «Разгрузы» и показывают
  всё, что завела команда.
- **Трубки** — общий список заказов, тот же, что открывается с дашборда.
- **Статистика** — общесистемные цифры: оборот за сегодня (пока нули, суммы заказов не
  складываются), трубки по стадиям и справочники — города по статусам, сколько ног
  и разгрузов.

В шапке любого раздела, открытого из профиля, слева появляется стрелка «Назад в профиль».
При заходе на тот же экран из таббара или с дашборда её нет — возвращаться туда неоткуда.

«Мои разгрузы» — единственный список, который в профиле режется дополнительно: Администратор
видит здесь только заведённые им разгрузы. Чужие остаются доступны с дашборда, где справочник
показан целиком.

У роли «Нога» разделов нет — ей остаётся только карточка профиля.

## Тесты

Из `backend/` с активированным venv:

```bash
python tests/test_delete_user.py
python tests/test_nogas.py
python tests/test_cities.py
python tests/test_noga_personal.py
python tests/test_admin_scope.py
python tests/test_profile_rename.py
python tests/test_trubki.py
```

Каждый скрипт использует свою БД (`data/test_delete.db`, `data/test_nogas.db`,
`data/test_cities.db`, `data/test_noga_personal.db`, `data/test_admin_scope.db`,
`data/test_rename.db`, `data/test_trubki.db`) и не трогает рабочую.

## Чеклист приёмки

1. **Owner** (`OWNER_TELEGRAM_IDS`): `/start` → кнопка → кабинет с именем и ролью Owner;
   в «Профиле» пять разделов, включая «Пользователи».
2. **Нога**: Owner добавляет через `/adduser <id> noga` или UI → у ноги свой кабинет, карточка общего оборота скрыта, нет управления пользователями; в «Профиле» только карточка.
3. **Посторонний**: `/start` и Mini App → «Доступ закрыт» / `NOT_ALLOWED`.
4. Dev: браузер + `DEV_AUTH_ENABLED` → вход по ID Owner работает.
5. **Администратор**: нижняя панель «Панель / Ноги / + / Города / Профиль»; на «Ногах»
   и «Городах» только свои записи; чужой город из витрины «В работе» открывается, но
   не правится; город в работе без ног светится красным предупреждением. В «Профиле»
   четыре раздела без «Пользователей», а «Мои разгрузы» показывают только его разгрузы.
6. **Разгрузы**: свои правятся и удаляются, чужие только читаются; удаление привязанного
   разгруза сначала спрашивает про города, а в новом городе свои разгрузы уже отмечены.
7. **Ник**: у Owner, Правой руки и Администратора в «Профиле» рядом с ником есть карандаш —
   имя меняется и сразу видно в шапке панели; «Ник!» и однобуквенный ник не сохраняются,
   у роли «Нога» кнопки нет.
8. **Трубки**: «+» в панели → «Трубка» → статус и город → сумма и нога; после создания
   проверить пересчёт 10%, фото денег, сумму USDT, фото чека, историю и отправку отчёта.
   Город с трубкой не удаляется.
